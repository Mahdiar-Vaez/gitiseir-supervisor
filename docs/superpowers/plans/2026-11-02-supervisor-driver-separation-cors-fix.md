# برنامه پیاده‌سازی تفکیک کامل اپ راننده و سرشوفر، رفع مشکل CORS ورسل و اتصال Vercel MCP

> **راهنمای مجری:** این سند گام‌به‌گام برای تفکیک قطعی اپ راننده و سرشوفر، رفع خطای CORS در نسخه وب ورسل، و افزودن Vercel MCP تهیه شده است.

**هدف:** تفکیک هویت بصری، روت‌ها و قابلیت‌های اپ راننده و سرشوفر، رفع خطای CORS نسخه وب از طریق Vercel Reverse Proxy، و تنظیم سرور Vercel MCP.

**معماری:** 
۱. استفاده از قابلیت Rewrites در `vercel.json` برای فوروارد کردن `/api/:path*` به `https://backend.vaezprojects.ir/api/:path*` در سمت سرورهای Edge ورسل (حل قطعی CORS بدون دستکاری بک‌اند).
۲. تنظیم هوشمند `API_BASE_URL` در `client.ts` که روی وب از روت‌های نسبی و روی نیتیو از دامنه مستقیم استفاده کند.
۳. تفکیک کامل لایه‌ها، تب‌ها، متون لاگین، کارت شناسایی و برندینگ بین دو مخزن `gitiseir-app` و `gitiseir-supervisor`.
۴. اتصال Vercel MCP Server به فایل کانفیگ `~/.gemini/config/mcp_config.json`.

## ۱. تحلیل ریشه‌ای مشکلات

### ۱.۱. چرا هر دو نسخه در ورسل یکی هستند؟
در دورهای قبلی به دلیل دستور «هیچ کاممیت و پوشی نکن»، تغییرات توسعه‌داده‌شده برای سرشوفر (بورد روزانه، تب لنگی، پروفایل سرشوفر، context ناوگان و تم فیروزه‌ای) **صرفاً روی سیستم شما ذخیره شده بودند و به گیت‌هاب پوش نشده بودند**.
وقتی ورسل مخزن `gitiseir-supervisor.git` را از گیت‌هاب می‌خواند، کاممیت قبلی (`ce3bad0`) را بیلد می‌کرد که در آن کاممیت:
- صفحه لاگین عنوان «سامانه رانندگان گیتی‌سیر» را داشت.
- تب‌ها شامل «کارت راننده» و «خانه» راننده بودند.
- تب لنگی و context سرشوفر هنوز به گیت اضافه نشده بودند.
در نتیجه، هر دو لینک ورسل خروجی اپلیکیشن راننده را نشان می‌دادند!

### ۱.۲. چرا در نسخه وب خطای CORS رخ می‌دهد در حالی که در `appsettings` ست شده است؟
با تست مستقیم `curl -v -X OPTIONS` مشخص شد وب‌سرور Nginx که جلوی سرور دات‌نت قرار دارد، درخواست‌های Preflight (OPTIONS) مرورگر را قطع کرده و پاسخ `204 No Content` خام **بدون هدر `Access-Control-Allow-Origin`** ارسال می‌کند. به همین دلیل حتی اگر در کد دات‌نت یا `appsettings.json` تنظیم شده باشد، مرورگر پیش از رسیدن به دات‌نت ارتباط را مسدود (Block) می‌کند.
**راهکار استاندارد ورسل:** بازنویسی روت‌ها (Rewrites Proxy) در `vercel.json`؛ مرورگر درخواست را به دامنه خود ورسل ارسال می‌کند (Same-Origin بدون CORS) و سرور ورسل آن را به بک‌اند تحویل می‌دهد.

### وظیفه ۲: حل قطعی خطای CORS در نسخه وب هر دو پروژه
**فایل‌ها:**
- ویرایش: `e:\projects\gitiseir-app\gitiseir-app\vercel.json`
- ویرایش: `e:\projects\gitiseir-supervisor\vercel.json`
- ویرایش: `e:\projects\gitiseir-app\gitiseir-app\src\services\api\client.ts`
- ویرایش: `e:\projects\gitiseir-supervisor\src\services\api\client.ts`

**گام‌ها:**
- [ ] افزودن روت پرکسی به `vercel.json`:
  ```json
  {
    "buildCommand": "npx expo export -p web",
    "outputDirectory": "dist",
    "cleanUrls": true,
    "framework": null,
    "rewrites": [
      {
        "source": "/api/:path*",
        "destination": "https://backend.vaezprojects.ir/api/:path*"
      },
      {
        "source": "/(.*)",
        "destination": "/index.html"
      }
    ]
  }
  ```
- [ ] در `client.ts`: در صورتی که پلتفرم وب باشد (`Platform.OS === 'web'`) و در محیط پروداکشن وب اجرا شود، `API_BASE_URL` به صورت مسیر نسبی خالی `''` عمل کند تا درخواست از طریق پرکسی ورسل بدون چک CORS پردازش شود؛ در پلتفرم نیتیو (`ios` / `android`) همچنان مستقیماً به `https://backend.vaezprojects.ir` ارسال شود.
